# 手机错误日志与自愿分享

## 用户要求：仅错误，不是按键行为分析

手机添加运行错误日志，记录错误的发生时间、触发模块和可用于诊断的错误信息。绝不记录用户点击了什么按键、具体用了哪个快捷键、输入了什么文本。

已有首次社区/匿名分享提示需要调整或衔接为清楚的错误诊断选择。用户明确选择分享后，错误才上传到我们的中心服务器；拒绝或尚未选择时，只保存在手机本地。

“中心服务器”不是配对电脑、LAN Desktop 主机或任意第三方分析服务。

## 本地记录范围

允许记录的结构化字段建议为：

- 错误事件的随机 ID（仅用于去重，不是长期用户/设备追踪 ID）。
- 发生时间，以及 App 版本/构建、产品 edition、平台。
- 固定模块和触发类别，例如连接、App 激活、快捷键传输失败、图标下载、配置加载、文件保存。
- 固定错误码、严重性、经过清理的简短错误说明、重复计数。

这里“快捷键传输失败”只表示模块发生错误；不得附带快捷键名称、键值、组合键、按钮位置、具体命令或发送内容。

禁止写入本地日志，也禁止上传：

- 按键点击历史、键码、快捷键组合或名称、具体按钮、输入文本、剪贴板、语音转写/录音。
- 鼠标移动/点击序列，截图或其他用户内容。
- 配置中的完整命令、用户文件路径、文档标题、账号标识。
- 认证 token、连接 code、请求 header、私有网络地址、URL 参数中的秘密。
- 未清理的任意 exception.toString / 原始 stack trace / 网络请求体。它们可能带上述内容。

采用固定错误分类和字段白名单；不能先把全部用户行为记下来，再仅在上传时脱敏。现有 UI 错误提示、平台通道失败、连接/下载/存储错误应接入同一清理入口。日志写入失败不能导致功能崩溃，也不能递归无限记录自己。

## 本地查看与保存

- 设置页增加“错误日志”入口，能查看时间、模块、错误说明和重复次数。
- 提供清除本地日志。若提供导出，必须由用户手动发起，仍使用同一脱敏数据。
- 使用有上限的滚动存储与可配置保留期；建议先采用最近 1000 条或 5 MiB 上限，超出按最旧条目淘汰并在文档中写明策略。
- 正常成功操作不产生行为日志。相同错误可合并计数，避免刷屏。
- 用户不分享时，错误日志照常本地保存；不能偷偷上传，也不能为了正常使用强制用户同意。

## 首次授权与设置

建议文案方向：“是否分享匿名错误诊断，帮助改进 LumiaKey？只发送脱敏错误，不包含按键、快捷键内容或输入文本。你可以随时关闭。”

- 独立错误诊断授权，例如 `shareErrorDiagnostics`，默认关闭 / 未决定时不上传。
- “允许分享”和“仅保存在本机”都清楚可选，不预选同意，不阻挡正常使用。
- 原来的社区设置、匿名统计或其他 consent 不能视为新错误诊断上传授权；已有安装升级后也不能默认开启。
- 开始页说“分享 usage”但实际发的是错误，应改为准确的“错误诊断”文案，不收集具体使用行为。
- 设置中可随时开启/撤销，界面明确显示当前是本地还是允许分享。
- 撤销后停止后续上传，取消尚未发送的队列和定时重试；本地日志保留。
- 后来开启时默认只分享开启后的错误；不自动回传之前拒绝分享期间积累的日志。若要分享历史记录，必须另有明确的手动选择。

## 中心服务器与上传

- 使用单独、明确配置的中心 HTTPS endpoint，例如 `POST /v1/diagnostics/errors`；不是 Desktop Companion 的 LAN endpoint。
- 小批量、限长、服务器去重、有限退避重试；离线不阻塞 UI，不发每次按键或成功操作事件。
- 服务器再次进行字段/长度/错误码校验，不接受任意用户 JSON 或原始日志转储。
- 控制保留期和容量。诊断记录不能公开混入图标网页、公共排行榜或账号备份。
- 请求本身会经过网络基础设施，不得向用户承诺网络层绝对匿名；本功能应做到不附带用户/设备身份、不收集输入行为。
- 后端测试涵盖未知字段、超大内容、重复批次与错误响应。中心服务不可用时，错误保留本机并显示合适状态，上传失败不能形成无限日志/上传循环。

## 产品边界

两个手机版都可以提供本地错误日志。用户之前确认的蓝牙精简版边界不包含网络/在线服务，因此本交接默认保持 Lite 仅本地日志，不为诊断暗中增加网络权限；自愿上传先用于完整版。若要让 Lite 也上传，必须把它作为联网边界的明确例外再向用户确认，而不是擅自改变已确认产品边界。

本功能不新增任何快捷键/按键行为分析。审查现有统计/社区分享代码时，不要把它的数据或授权混进这个错误诊断通道。

## 必须验证的路径

1. 默认/未选择/拒绝分享时产生错误：只写本地，零中心网络请求。
2. 明确允许后产生错误：发送到中心服务器，字段不含键码、快捷键、输入、token 等内容。
3. 使用正常键盘、快捷键和触控板：不生成行为日志。
4. 错误对象含模拟 token、路径、剪贴板/组合键等敏感内容：本地和上传均不保留这些值。
5. 从允许改为拒绝：待发送和重试立即停止；旧本地日志仍可查看。
6. 从拒绝改为允许：不会自动补发历史错误。
7. 离线/中心服务失败/日志存储失败：不阻塞用户输入，不崩溃、不无限重试。
8. 老版本社区分享已启用的升级场景：不能据此自动开启错误分享。
9. Lite 本地模式不会请求网络/麦克风或偷偷启动上传服务。
10. 首次授权、本地日志列表、空日志、错误详情、清除确认、分享设置和上传异常状态都有当前版本截图并汇总到一个 index。
